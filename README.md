# Music-service

## Описание
Каталог музыки с ролевой системой доступа.

## Роли пользователей

### USER (Обычный пользователь)
- Просмотр музыки
- Управление своими плейлистами

### ADMIN (Администратор)
- Все права обычного пользователя
- Управление пользователями (просмотр, удаление)
- Управление музыкой (добавление, удаление)

## API Endpoints

### Публичные эндпоинты
- `POST /api/user` - Регистрация пользователя

### Эндпоинты для пользователей (USER, ADMIN)
- `GET /api/music` - Получить все песни
- `GET /api/music/{id}` - Получить песню по ID
- `GET /api/playlist/**` - Управление плейлистами

### Админские эндпоинты (только ADMIN)
- `GET /api/admin/users` - Получить всех пользователей
- `GET /api/admin/users/{id}` - Получить пользователя по ID
- `DELETE /api/admin/users/{id}` - Удалить пользователя
- `POST /api/admin/music` - Добавить новую песню
- `DELETE /api/admin/music/{id}` - Удалить песню

## Аутентификация
Используется HTTP Basic Authentication. При создании пользователя роль по умолчанию - USER.

### Роли и права доступа

#### 🔐 USER (Обычный пользователь)
- **Просмотр музыки**: Получение списка песен и информации о конкретных песнях
- **Управление плейлистами**: Создание, редактирование и удаление своих плейлистов
- **Регистрация**: Создание нового аккаунта

#### 👑 ADMIN (Администратор)
- **Все права USER**: Полный доступ ко всем функциям обычного пользователя
- **Управление пользователями**: 
  - Просмотр всех пользователей системы
  - Получение информации о конкретном пользователе
  - Удаление пользователей
- **Управление музыкой**:
  - Добавление новых песен в каталог
  - Удаление песен из каталога

### Swagger UI
Документация API доступна по адресу: `http://localhost:8080/swagger-ui.html`

Для тестирования API в Swagger UI:
1. Нажмите кнопку "Authorize" в правом верхнем углу
2. Введите логин и пароль пользователя
3. Нажмите "Authorize"
4. Теперь вы можете тестировать API с вашими учетными данными

**Тестовые пользователи:**
- **Администратор**: логин `admin`, пароль `admin` (роль ADMIN)
- **Обычный пользователь**: создайте через POST /api/user (роль USER по умолчанию)

## Структура данных

### Музыка
- инвентарный номер
- жанр
- название
- исполнитель
- композитор
- тип носителя (CD/кассета/...)
- название фирмы звукозаписи
- дата записи

### Пользователь
- ФИО
- адрес
- телефон
- логин
- пароль
- роль (USER/ADMIN)

### Плейлист
- Связь пользователя с музыкой
